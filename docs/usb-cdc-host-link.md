# USB CDC 下位机通信（协议 v1）

> VOFA 适配更新：下位机交付版当前默认上传**二进制反馈（模式0）**；模式1保留 **FireWater 文本反馈**，设置和通道表见 [VOFA 反馈](vofa-feedback.md)。本文下述 STATUS 帧、上位机二进制对接要求 `host_feedback_mode=0`（二进制），静止切换后用 `host_status.feedback_mode` 确认。FireWater 不是本二进制协议的解码插件，两种反馈不混发。

本工程交付STM32固件和USB CDC v1二进制接口，ROS 2节点和串口/桥接实现由上位机负责人负责。本协议用于正常连续控制，无需短时运动测试程序。职责与交接步骤见 [下位机交接说明](lower-controller-handoff.md)。

2026-11-01 控制语义已按用户要求简化：收到 VELOCITY 自动使能，保持最新目标，不要求 ARM、固定发帧频率或递增序号。旧版250 ms主机期限不再适用。

2026-11-10 接入塔吊 yaw/z 的 X 固件绝对梯形位置控制：命令 `05/06/07`，独立反馈 `0x83`；原 STATUS (`0x81`) 与 POSE (`0x82`) 布局不变。两轴配置独立，参数只在 RAM 保存。实现和待上板验证项见[塔吊X42接入](crane-x-integration.md)。

2026-11-11 接入PE5/TIM9_CH1齿条舵机脉宽命令 `08`。命令以微秒指定绝对PWM高电平时间；板级当前接受500–2500 us，超范围拒绝且保留原输出。用户已确认动作正常并完成中位标定，当前板级上电值为2400 us，安全行程稍后标定。

同日新增PE6/TIM9_CH2夹爪舵机命令 `09`，两路独立实例、同为50 Hz；用户通过VOFA脉宽命令测试后确认动作和数据正常，并标定张开1000 us、夹紧550 us。当前板级上电输出1000 us（张开），软件允许范围仍为500–2500 us，安全行程待后续标定。动作验证不代表具备实测位置反馈。开合参数位于`board/board_servo.h`的`BOARD_GRIPPER_SERVO_OPEN_PULSE_US`和`BOARD_GRIPPER_SERVO_CLOSED_PULSE_US`，上电值由`BOARD_GRIPPER_SERVO_CENTER_PULSE_US`单独设置。未接入另外两个舵机。

同日接入夹取/放下联动：`0A`、`0B`分别触发，`84`独立反馈。用户已确认动作顺序、两组工作坐标和安全z=0；当前两动作均已配置并启用，收到合法启动事件且反馈就绪时执行。实现、配置入口和验证见[联动说明](crane-pick-place-design.md)。

## CubeMX 配置核对

| 项目 | 当前配置 |
| --- | --- |
| MCU | STM32F407VET6 |
| USB | USB_OTG_FS / Device Only / CDC |
| D− / D+ | PA11 / PA12 |
| 晶振和 PLL | HSE 8 MHz，M=4，N=168，P=2，Q=7 |
| 系统 / USB 时钟 | 168 MHz / 48 MHz |
| VBUS sensing | 关闭；通过USB挂起、反初始化或重新配置事件停止，无主机命令期限兜底 |
| IRQ | OTG_FS 优先级 5；USB 回调不调用 RTOS API |
| 初始化 | `defaultTask` 调用 `MX_USB_DEVICE_Init()`，注册 CDC 类和接口并启动 USB |

以上配置与当前生成代码一致，本轮不修改 `.ioc` 或外设初始化区域，无需重新生成 CubeMX。USB 用户回调的接入保留在 `USER CODE` 区。连接 **MCU 原生 USB FS 插座**，ST-Link 的 USB/虚拟串口不是这条链路。需要能传数据的 USB 线。

CDC 串口工具可选择 115200；这里传输的是 USB 数据，CDC 的 line-coding 波特率不会改变实际 USB 速率，也不会改变电机 UART5 的 115200 配置。普通文本串口助手会显示二进制数据，正式对接需由上位机按本协议解析。

| `system/robot_task.c` | 唯一 motorTask 调用更新入口、发布调试状态快照 |

USB 接收中断只复制字节和 HAL 接收时间，再重启 OUT 接收。512 字节静态环形缓存满时丢弃当前包并清空旧数据、递增连接代次和溢出计数；不部分接收或覆盖。任务每次最多处理一环缓存；连接代次变化会停止当前主机控制并丢弃本轮输入。已完整接收的命令不因任务处理延迟达到100 ms而丢弃或停机；接收时间仅供解析字节间隔和诊断使用。

TX 使用独立静态存储，直到 IN 完成才可复用；挂起恢复不能提前释放发送缓冲。类重新初始化后重新允许发送。二进制反馈每25ms尝试一帧，STATUS/POSE各名义20Hz；绑定塔吊时空闲时隙另发CRANE反馈，名义20Hz，再用空闲时隙发送ACTION反馈，名义10Hz。FireWater不混发CRANE/ACTION。原两类成功提交后轮换类型，忙时保留待发送类型，下次编码最新快照，不排队重发旧状态。`tx_skipped` 在未连接或电脑不读取时增加是可能的。

## 帧格式

所有多字节数均为小端整数，显式按字节编码，不直接发送 C 结构体。

| 字节偏移 | 字段 | 长度 |
| --- | --- | --- |
| 0 | 帧头 `A5 5A` | 2 |
| 2 | 版本 `01` | 1 |
| 3 | 类型 | 1 |
| 4 | payload 长度 `uint16` | 2 |
| 6 | 序号 `uint32` | 4 |
| 10 | payload | N |
| 10+N | CRC16 小端 | 2 |

CRC 为 CRC-16/CCITT-FALSE，poly=0x1021，init=0xFFFF，不反射、无末尾异或；覆盖帧头到 payload 最后一个字节，标准向量 `123456789 → 0x29B1`。输入最大 24 字节，输出帧最大容量 240 字节。支持拆包/粘包，输入字节间隔 ≥100 ms 丢弃半帧，错 CRC/长度/版本后扫描下一帧头。

| 类型 | 含义 | payload |
| --- | --- | --- |
| `01` | VELOCITY | 三个 `int32`：vx mm/s，vy mm/s，wz mrad/s，共 12 字节 |
| `02` | ARM | 0 字节，可选零速预使能；运行或已有启动请求时忽略 |
| `03` | STOP | 0字节，全局停止：底盘停止并失能；塔吊两轴停止并保持使能 |
| `04` | POSITION | 三个 `int32`：绝对X mm、Y mm、yaw mrad，共12字节 |
| `05` | CRANE_TARGET | 12字节，单轴多圈绝对位置目标，见下表 |
| `06` | CRANE_CONFIG | 12字节，更新指定轴之后目标所用的速度/加速度参数 |
| `07` | CRANE_STOP | `axis:u8`；通常只停指定轴，联动运行中会取消整个联动并停两轴 |
| `08` | SERVO_PULSE | `pulse_us:uint16` little-endian，设置齿条舵机脉宽，2字节 |
| `09` | GRIPPER_SERVO_PULSE | `pulse_us:uint16` little-endian，设置夹爪舵机脉宽，2字节 |
| `0A` | CRANE_PICK | 0字节，触发一次夹取事件，按sequence去重 |
| `0B` | CRANE_PLACE | 0字节，触发一次放下事件，按sequence去重 |
| `0C` | CRANE_DISABLE | `axis:u8`，显式释放指定轴保持力，用于手动找点；持续读取反馈 |
| `81` | STATUS | 196 字节，名义20 Hz；总帧长208字节 |
| `82` | POSE | 64字节，名义20 Hz；总帧长76字节，见[位置反馈扩展](position-feedback.md) |
| `83` | CRANE | 116字节，名义20 Hz；总帧长128字节，紧随STATUS/POSE空闲USB时隙发送 |
| `84` | ACTION | 40字节，名义10 Hz；总帧长52字节，联动实例已初始化时发送 |

塔吊轴编号 `0=yaw`、`1=z`。输入位置是驱动器 `0x36` 同一单位：带符号累计 `0.1°/电机轴单位`，每电机轴圈3600，不取单圈模、不乘齿轮比/丝杆导程。范围为 `-4294967295..4294967295`；正负号是相对于驱动器零点的绝对坐标符号。每条塔吊输入帧的 sequence 可重复或不递增，只按接收顺序处理。

| 命令载荷偏移 | CRANE_TARGET `05` | 长度 |
| --- | --- | --- |
| 0 | axis：0 yaw / 1 z | 1 |
| 1..3 | 保留，必须为0 | 3 |
| 4..11 | `int64` little-endian 绝对 `position_units` | 8 |

| 命令载荷偏移 | CRANE_CONFIG `06` | 长度 |
| --- | --- | --- |
| 0 | axis：0 yaw / 1 z | 1 |
| 1..3 | 保留，必须为0 | 3 |
| 4..5 | `uint16` little-endian 最大速度，0.1 RPM，范围1..30000 | 2 |
| 6..7 | `uint16` little-endian 加速度，RPM/s，范围1..65535 | 2 |
| 8..9 | `uint16` little-endian 减速度，RPM/s，范围1..65535 | 2 |
| 10..11 | 保留，必须为0 | 2 |

板级初始值分别配置在 `board/board_crane.h`：yaw默认10RPM，z按用户要求提高10倍至100RPM（协议字段1000）；两轴加/减速度仍各100RPM/s，目标到达窗口为驱动器位置反馈±10单位（1°电机轴）。这些是当前配置，不代表机构速度/行程已标定。CONFIG 即刻影响 RAM 中的下一条不同目标，不改动正在运行的轨迹，也不写驱动器Flash；复位后恢复板级初值。每次把配置与新目标的速度/加减速快照进该目标，手动z目标和联动均沿用该轴配置。

| CRANE 反馈载荷偏移 | 含义 | 长度 |
| --- | --- | --- |
| 0..3 | 编码时间，ms | 4 |
| 4..59 | yaw 轴记录 | 56 |
| 60..115 | z 轴记录 | 56 |

每轴记录均为：`actual:i64LE` (0)、`target:i64LE` (8)、`sequence:u32` (16)、`generation:u32` (20)、位置/状态反馈时间 `u32` (24/28)、拒绝命令计数 `u32` (32)、flags `u32` (36)、motion state `u8` (40)、fault `u8` (41)、原始驱动状态 `u8` (42)、保留0 (43)、速度/加速度/减速度 `u32` (44/48/52)。flags bit0位置有效、bit1状态有效、bit2驱动使能、bit3驱动原始到达位、bit4目标活动、bit5本代 `0xFD` 已接受、bit6停止/失能待确认、bit7板级实例已初始化、bit8显式失能意图。bit8不代表已经失能，必须结合bit1=1、bit2=0、bit6=0确认。实际值即使无效仍回传最后数值，使用前必须检查有效位。

motion state：0空闲、1等待使能/目标发送、2运动中、3目标已到达、4停止确认中、5故障、6显式失能确认中。fault：0无、1反馈超时、2堵转/保护、3运行中意外失能、4命令拒绝、5控制帧应答超时、6串口传输错误、7 USB链路异常。只对 `0xFD` ACK之后收到的位置与状态新样本、驱动原始到达位及位置误差同时满足±配置窗口时置到达；随后位置/状态数据过期会撤销到达状态。

示例：yaw 绝对目标 `+360` 单位、sequence=1：`A5 5A 01 05 0C 00 01 00 00 00 00 00 00 00 68 01 00 00 00 00 00 00 49 45`。yaw 设置10RPM和100/100RPM/s：`A5 5A 01 06 0C 00 01 00 00 00 00 00 00 00 64 00 64 00 64 00 00 00 05 54`。停止yaw：`A5 5A 01 07 01 00 01 00 00 00 00 97 32`。

示例 ARM(seq=1)：`A5 5A 01 02 00 00 01 00 00 00 4B 4C`。

示例齿条舵机脉宽(seq=1，1500 us，非当前标定中位)：`A5 5A 01 08 02 00 01 00 00 00 DC 05 DF D1`。另一示例(seq=2，1600 us)：`A5 5A 01 08 02 00 02 00 00 00 40 06 DA 72`。齿条当前上电中位为2400 us，发上述命令会离开该位置，测试目标按实际机构余量选取。

夹爪张开(seq=1，1000 us)：`A5 5A 01 09 02 00 01 00 00 00 E8 03 6B 93`。
夹爪夹紧(seq=1，550 us)：`A5 5A 01 09 02 00 01 00 00 00 26 02 11 B6`。

在VOFA选择HEX发送，不附加CR/LF。夹爪启动时，板级初始化先将CH2比较值写为配置的上电脉宽（当前1000 us），再启动该路PWM；CubeMX生成的初始CH2值250在启动前被覆盖，不是最终上电脉宽。中位和范围分别在`board/board_servo.h`的`BOARD_RACK_SERVO_*`与`BOARD_GRIPPER_SERVO_*`中配置。开合标定值不作为软件上下限；安全行程另行标定。命令单次设置并保持绝对脉宽，不提供实测位置或到达反馈；序号可重复。`08`只影响齿条，`09`只影响夹爪，越界拒绝计入STATUS的control_rejected。全局STOP及USB异常不改变两路舵机脉宽、不关闭PWM；不自动松爪或回中。

示例速度(seq=0xFFFFFFFF，vx=−50，vy=25，wz=−300)：
`A5 5A 01 01 0C 00 FF FF FF FF CE FF FF FF 19 00 00 00 D4 FE FF FF 47 91`。

## 夹取 / 放下联动

夹取(seq=1)：`A5 5A 01 0A 00 00 01 00 00 00 E6 DF`。
放下(seq=1)：`A5 5A 01 0B 00 00 01 00 00 00 87 67`。
VOFA使用HEX发送、不加CR/LF。当前板级已启用两动作：安全z=0；夹取yaw=153、z=37121、前后2400 us；放下yaw=2816、z=22315、前后2400 us。下载本次固件后，两个示例会在满足启动条件时执行联动。修改坐标入口为`board/board_crane_action.h`，需重新编译烧录；任一`*_CONFIGURED`置0可禁用对应动作。

流程为：z安全高度→yaw到位→前后到位→z工作高度→夹紧550 us或张开1000 us→z安全高度。夹取的前后步骤同时先张开1000 us，放下保持现有夹爪输出直到工作高度到达。yaw/z每步要求目标generation/坐标一致、FD已接受、步骤开始后两类新反馈、有效实测位置/状态和到达窗口；已由联动接管的轴也须仍到达才能继续。前后初始等待1000ms，夹爪初始等待500ms；每步总超时120000ms，均为待实机整定值。舵机完成依据是时间，不是实测位置或物体检测。

启动时需无未到达的手动塔吊目标、无停止待确认且两轴位置/状态新鲜、无堵转/保护；未就绪不排队。运行中拒绝05/06/08/09和另一条联动启动；底盘原控制保持独立。03取消整段并执行原全局停止；运行时07也取消整段并停两轴，该接收批次后续命令丢弃。USB异常、轴异常或步骤超时终止整段，停止步进轴并保持使能；舵机保持当前输出，不自动松爪/回中或恢复旧步骤。异常取消后需停止确认、故障恢复和新事件才能重新执行。

联动是单次事件：按夹取/放下各自记忆的最近接受sequence去重。同一种动作相同sequence即使完成、取消或失败也不重启；再次执行必须更换sequence，但不要求递增。不同动作可各用sequence=1。拒绝的启动不占用sequence；复位后去重记录清空。其他旧目标命令（01/04/05等）的固定序号语义不变。重复旧事件幂等返回，不改当前动作状态；没有额外ACK帧。

`84`载荷多字节字段均小端，布局如下：

| 偏移 | 类型 | 内容 |
| --- | --- | --- |
| 0 | u32 | 编码时间ms |
| 4 | u32 | 最近接受的联动sequence |
| 8 | u32 | 接受的新联动generation |
| 12 | u32 | 联动启动拒绝计数；同时计入STATUS control_rejected |
| 16 | u32 | 当前/终止步骤已用时间ms，非整段累计时间 |
| 20 | u8 | state：0空闲、1运行、2完成、3取消、4故障 |
| 21 | u8 | action：0无、1夹取、2放下 |
| 22 | u8 | step：0无、1安全z、2yaw、3前后、4下降、5夹爪、6抬升 |
| 23 | u8 | fault：0无、1显式停止、2USB异常、3轴异常、4超时、5输出拒绝、6目标被覆盖 |

## 塔吊控制契约

- 上电只轮询反馈，无自动使能/运动/回零等待；操作者按已定流程等驱动自动回零后再发目标。收到目标时必须有新鲜位置和状态、无堵转/保护，否则拒绝，不缓存待启动。
- 一条目标发送一次普通 `FD` 绝对梯形位置帧；若电机失能，先发 `F3 AB 01 00 6B` 并等新的使能状态，再发FD。已经使能的轴直接发FD。无需ARM、周期续发或递增sequence；参数错误/保留位非0/轴号非法不会覆盖旧目标。
- 同一活动目标重复发送只回显sequence，不重发FD，不重置generation；改变坐标覆盖旧目标，任务内待发目标为单槽最新值。在途串口帧不撤回，完成后发送最新目标。运动中覆盖能力依赖驱动器实际X固件，尚待本机验证。
- 正常到达后保持目标与使能，持续读反馈。驱动FD `02`只证明指令接受；异步 `FD 9F`仅计数，不能直接当作当前目标到达。
- STOP/单轴STOP/活动轴USB挂起、掉线、重配、RX溢出会取消对应目标并发 `FE 98 00 6B`，塔吊不发送失能，尤其z轴保持驱动力矩。无主机续期。未活动轴的启动/初次USB连接不发停止。
- 单轴模式下，活动轴反馈500ms超时、堵转/保护、运行中失能、串口故障、控制帧拒绝或应答超时取消本轴并停止，不联动另一塔吊轴或底盘；夹取/放下联动运行中则取消整段并停止两轴。通信恢复不续发旧FD。停止指令失败后查询新状态，确认已失能则结束停止，否则继续尝试FE；停止待确认时新目标被拒绝。故障原因保留供观察，新外部目标在反馈正常、无堵转且停止已确认时恢复。
- `0x83`分别报告两轴独立状态，与底盘mode和POSITION到达无关。上位机按 `type/length` 分流所有反馈，反馈帧sequence可能因新类型而不连续。模式1 FireWater仍只含原22个底盘通道；模式切换在塔吊有活动目标/停止待确认时也会拒绝。

## 手动找点与分轴失能（0C）

VOFA选择HEX发送，不附加CR/LF：yaw `A5 5A 01 0C 01 00 01 00 00 00 00 38 E4`，z `A5 5A 01 0C 01 00 01 00 00 00 01 19 F4`。z轴先支撑负载，再释放保持力；保持驱动器供电。

收到后取消本轴旧目标，发`addr F3 AB 00 00 6B`，再查新的3A失能状态；ACK本身不能确认。若仍使能或查询失败则继续尝试，期间拒绝新目标；确认后恢复36/3A交替查询，不自动重发旧目标。下一条独立的新05目标或联动事件仍可自动使能，不是永久运动锁。03/07或USB异常可取消尚待确认的失能意图，恢复原FE停止策略；它们不主动使能已经失能的轴。失能和07一样屏蔽同批次后续同轴命令/联动事件；联动运行中0C先取消整段并停止两轴，再仅失能指定轴，丢弃本批次后续命令。

调试器记录`crane_status.axes[0].feedback.position_units`（yaw）、`crane_status.axes[1].feedback.position_units`（z），并检查对应`position_valid=true`、`status_valid=true`、`enabled=false`、`motion.stop_pending=false`。手动转动后数值及position_ms应持续更新，记录带符号累计值，不取模、不清零、不看motion.target_units。手动多圈累计连续性须在实物失能状态下核对；软件继续使用驱动36回复，不自行补圈。新失能功能已编译/离线验证，尚未烧录或实机确认。

## 底盘控制契约与恢复

上电不运动；USB枚举和状态反馈不会使能。收到一条有效 VELOCITY 即保存目标，待总线和四轮反馈就绪后自动使能，不需要先发ARM。

1. VELOCITY 三轴值使用整数 mm/s、mrad/s，转换为应用层 m/s、rad/s；`x`向前、`y`向左、正`wz`俯视逆时针。
2. 使能过程中允许直接发送非零目标，新速度覆盖旧目标。四轮均取得本次使能之后的新状态才输出；实际使能操作超过500 ms仍未确认则停止。
3. 速度目标保持到新的VELOCITY、POSITION或STOP（故障/USB异常也取消），不设置250 ms主机期限，不要求20 Hz续发。sequence仅用于回传，可重复、倒序或固定为0，按接收顺序覆盖。
4. 取消每轴±0.1 m/s和±0.5 rad/s越界停机规则及20 RPM轮速上限。载荷可编码完整int32范围；底盘直接解算四轮速度，不做比例缩放。驱动协议仍只支持原生±5000字段单位（名义1 RPM/单位），超出时进入MOTOR_ERROR并停止，不截断或回绕。
5. 零速度使四轮零速保持，仍使能；STOP清零目标并请求停止失能。可选ARM用于零速预使能，运行中或已有启动请求时重复ARM忽略。

STOP所在接收批次的后续输入丢弃。停止确认中重复STOP不延长期限；后续独立批次的新速度可以保存，待停止完成后再自动使能。1秒内未取得四轮新鲜失能反馈则STOP_TIMEOUT，并再请求停止失能。当前失能事务失败后持续重试仍有已知缺口，失能须以四轮新鲜反馈确认，不能仅看STOP已发送。

偶发EMM查询超时保留尚新鲜的历史反馈并继续轮询；单纯协议错误计数增加不再触发应用停机。实际控制写失败、驱动明确拒绝、500 ms反馈失效、失能、堵转及UART传输故障仍会停止。底层每轮200 ms输出刷新检查保留，motorTask每50 ms自动刷新已保存目标，它不是ROS/USB主机命令期限。

USB挂起、反初始化、重新配置及接收溢出会清除旧目标；恢复后需要新的VELOCITY或满足定位条件的POSITION，旧目标不会自动恢复。首次配置变化所在接收批次会丢弃，上位机应先读取STATUS再发首条速度。首条速度若早于电机反馈到达，会保留到就绪再启动，此时state可暂为DISABLED（或原FAULT），开始实际使能后变为ENABLING；STOP或USB异常会取消该请求。

主机停止发帧、ROS节点退出但USB仍保持配置时，下位机会继续保持最后速度。ROS侧需要停车时发送零速度或STOP；物理拔线的停止依赖USB挂起/断开相关事件被识别，现已没有命令静默超时作为兜底。

### 位置目标

POSITION自动申请使能，X/Y/yaw为相对启动原点的绝对目标，应用层使用m、rad，线协议使用mm、mrad。位置环每50ms计算一次速度；容差内输出零速并保留使能，稳定到达后仍保持位置。相同坐标重复发帧不增加行程、不重置到达计时。

POSITION需要定位有效且底盘不在STOPPING，否则仅增加拒绝计数；VELOCITY（包括零速）取消位置模式，ARM在位置模式中忽略。STOP/USB异常/设备故障/定位失效取消位置目标，恢复后需新命令。位置控制参数、接受条件、目标关联和到达语义见[位置反馈扩展](position-feedback.md)。

### 方向和反馈单位

板级四轮安装方向都为 −1，同时用于 SI 目标与测量反馈。原 `position_raw` 保留驱动器原始累计位置，不反转；`wheel_speed_rad_s` 为经过方向换算的轮轴实测速度。当前按 65536 位置计数/圈差分，速度命令按名义 1 RPM/字段单位转换。此前实测字段 20 约 19.08 RPM，未据此拟合补偿。几何尺寸仍暂用 240×240 mm，轮径 75 mm；未完成精确尺寸和完整圈数校准，不能把当前速度/里程视为高精度标定结果。

四轮通过 UART5 顺序发送速度帧，尚未实现 EMM 驱动器的同步触发指令；这里的一路四地址控制不等于四台驱动器同时启动。

## STATUS payload

下表偏移均相对 payload；有符号 milli 单位中的 `INT32_MIN` 表示无可用测量。命令和实测独立传输。无通用 ACK 帧，通过状态、最后接受的序号和拒绝计数判断执行结果。

| 偏移 | 类型 | 内容 |
| --- | --- | --- |
| 0 | u32 | MCU RTOS uptime_ms |
| 4…7 | 4×u8 | state、fault、connected、motion_allowed |
| 8 | u32 | last_command_sequence（最后接受的 ARM / VELOCITY / POSITION标记；允许重复或任意顺序） |
| 12 | u32 | control_rejected |
| 16…36 | 6×u32 | received_frames、crc_errors、format_errors、rx_overflows、tx_skipped、link_epoch |
| 40 | 3×i32 | requested：vx mm/s、vy mm/s、wz mrad/s |
| 52 | 3×i32 | applied：与requested相同的计算目标，未包含 RPM 整数取整误差；不代表已执行或实测速度 |
| 64 | 3×i32 | measured：实测底盘速度，同单位 |
| 76 | u32 | measured_valid |
| 80…96 | 5×u32 | 电机 bus timeouts、protocol_errors、rejected、transport_errors、rx_errors |
| 100 | 4×24 字节 | 依地址 1、2、3、4 的反馈块，见下表 |

| 每轮块偏移 | 类型 | 内容 |
| --- | --- | --- |
| 0 | i64 | position_raw，驱动器累计位置 |
| 8 | i32 | 实测轮速，mrad/s；无效为 INT32_MIN |
| 12 | u32 | position_ms |
| 16 | u32 | flags：bit0位置有效，1速度有效，2使能反馈有效，3已使能，4堵转反馈有效，5堵转，6堵转保护 |
| 20 | u32 | enabled_ms |

state：0 DISABLED，1 ENABLING，2 ACTIVE，3 STOPPING，4 FAULT。

fault：0 OK，1 COMMAND_TIMEOUT（保留，不再因主机静默产生），2 LINK_LOST，3 MOTOR_ERROR，4 ENABLE_TIMEOUT，5 STOP_TIMEOUT，6 INVALID_COMMAND（内部运动学输入异常），7 NOT_READY（位置模式定位不可用）。部分拒绝只增加计数而不改变 fault。

`measured_valid` 需要四轮位置和速度都有效、位置反馈年龄 <200 ms、四轮时间差 ≤80 ms，再做正解算。无效时速度字段为 INT32_MIN，不能用目标速度填补。反馈非硬件同步采样。MCU 时间未与 ROS 时钟同步，ROS 节点应记录接收时间并显式处理时间域。PB2 只表示任务心跳，不表示 USB 或驱动器一定正常。

## 对接与状态检查

固件默认模式0（二进制），不自动使能。上位机负责人依据 [交接说明](lower-controller-handoff.md) 实现收发、使能和停止确认。VOFA仅用于模式1的观测，正式模式不混入文本。

下位机调试器可查看 `host_status`、`chassis_control_status` 和 `motor_status`。`host_status.connected`只表示CDC配置/恢复状态，不证明ROS节点在线。旧手动运动模块及选择器已删除，停止使用USB STOP命令。
