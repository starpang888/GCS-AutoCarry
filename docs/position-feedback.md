# USB CDC位置目标与到达反馈扩展

本扩展与[主协议](usb-cdc-host-link.md)配合阅读，按2026-11-07正式源码核对。位置目标与位姿/到达反馈已接入；用户确认数据显示正常，ROS 2双方实机联调仍待完成。

## 公共帧

所有帧采用小端：A5 5A 01 type length:u16 sequence:u32 payload crc:u16。
帧头10字节，帧尾2字节。CRC-16/CCITT-FALSE：poly=0x1021、init=0xFFFF、不反射、不做末尾异或，覆盖帧头及载荷。
USB是字节流，必须支持任意拆包、粘包和未知type按长度跳过，不以USB包边界拆业务帧。

## 位置命令0x04（既有接口）

载荷12字节，依次为三个int32：X(mm)、Y(mm)、yaw(mrad)。它是固定起始坐标系下的绝对目标。
启动原点X=0、Y=0、yaw=0；X向初始车头前方，Y向初始左方，yaw逆时针为正。
不要求周期续发或递增sequence。重复同一目标不累加位移；改变坐标覆盖旧目标。
本扩展保留v1公共帧格式，增加POSITION控制和POSE反馈，不增加主机看门狗或底盘软件速度上限。

## 位姿反馈0x82

载荷固定64字节，总帧长76字节。下表偏移从payload起算（完整帧需再加10）。

| 载荷偏移 | 类型 | 含义/单位 |
| --- | --- | --- |
| 0 | uint32 | 本帧编码时间，启动后ms |
| 4 | uint32 | 最近位姿更新的任务时间，ms；须结合有效位 |
| 8 | uint32 | 最后接受的POSITION命令sequence |
| 12 | uint32 | goal_generation；进入位置模式或目标整数坐标变化时+1 |
| 16 | uint8 | robot_mode：0空闲、1速度、2位置 |
| 17 | uint8 | arrival_state：0无目标、1接近/条件未满足、2稳定计时、3稳定到达 |
| 18 | uint8 | 有效标志，见下表 |
| 19 | uint8 | 保留为0 |
| 20 | int32 | 当前固定坐标系X，mm |
| 24 | int32 | 当前固定坐标系Y，mm |
| 28 | int32 | 当前yaw，mrad，约[-3142,3142] |
| 32 | int32 | 最后接受的位置目标X，mm |
| 36 | int32 | 最后接受的位置目标Y，mm |
| 40 | int32 | 最后接受的位置目标yaw，mrad；保持原命令整数，不归一化 |
| 44 | int32 | 实测车体vx，mm/s |
| 48 | int32 | 实测车体vy，mm/s |
| 52 | int32 | 实测wz，mrad/s |
| 56 | uint32 | 有采样支持的稳定时长，ms；最多为所需时长 |
| 60 | uint32 | 配置要求的稳定时长，当前为300ms |

| flags位 | 含义 |
| --- | --- |
| bit0 | 当前位姿可用：里程计连续有效、无tracking_lost且年龄小于配置期限 |
| bit1 | 本帧实测速度可用：四轮位置/速度有效、年龄<200ms且四轮时间差<=80ms |
| bit2 | 当前生效的位置目标几何误差在容差内；不等于稳定到达 |
| bit3 | 当前正在执行位置目标；取消后为0 |
| bit4..7 | 保留为0 |

int32实测/位姿字段遇到无效或不能表示的数值写INT32_MIN；上位机还须检查有效位并自行处理接收中断。
固件内部位置m、角度rad换成毫单位时向零取整，因此上传量化结果不能替代固件内部浮点容差判断。
速度来自四轮编码器位置差分和运动学正解，不是目标速度，也不是外部定位或IMU融合结果。
当前yaw来自轮式里程计；陀螺仪尚未接入。

## 位置命令接受与模式切换

POSITION需要已绑定位置控制器、里程计已建立有效基准且未tracking_lost，当前底盘不能处于STOPPING。未满足时增加STATUS的control_rejected，不接受新目标、不更新位置序号/代次；待条件满足后重发。它与VELOCITY可等待初始设备反馈启动的行为不同。
接受POSITION后自动申请使能，不需要先发ARM；目标与到达反馈均不重置里程计原点。新POSITION覆盖旧目标，不排队。
VELOCITY（包括全零）取消位置控制，切到速度模式；ARM在位置模式中忽略，不会取消位置目标。STOP取消目标并请求整车停止失能；故障、USB异常或定位失效取消目标，恢复后需新的外部命令。定位失效在位置模式下报告fault=7（NOT_READY）。

## 到达语义

当前板级配置：kp_xy=0.5、kp_yaw=1.0，距离容差0.005m（5mm）、yaw容差0.0174533rad（约1°）。这些是判定参数，不代表已标定的真实定位精度。

稳定到达要求：底盘ACTIVE、几何误差在当前容差内、实测平移速率<=0.01m/s、角速度绝对值<=0.02rad/s，且连续满足至少300ms。
实际在50ms位置环周期内判定，四轮都取得新采样才推进时间；考虑轮询时间差，确认延迟可略大于300ms。
低速证据失效只撤销到达状态，不因此单独停机；原有设备故障和定位失效取消逻辑仍生效。
到达状态随当前条件变化，不是锁存事件。到达后保持使能并继续位置保持；偏离容差重新修正，低速条件不满足或速度无效重新计时。
STOP、速度模式切换、USB异常或设备故障取消位置目标，将arrival_state清零。最后目标坐标/seq/generation保留供诊断，bit3=0时不能当作仍在执行。

上位机以robot_mode=2、有效标志齐全且arrival_state=3认定当前目标稳定到达，并结合目标坐标、位置命令sequence和goal_generation关联。
sequence允许重复，不能单独据此区分任务；相同坐标在位置模式下即使换seq也不新建代次。
generation从0起递增、允许uint32回绕，MCU重启后重新开始，不能作为跨重启的永久任务ID。
0x82帧头sequence是发送反馈的计数，与payload里的命令sequence不同。

## 发送频率与兼容性

二进制模式0：每25ms尝试发送一帧，STATUS(0x81，196字节载荷/208字节总长)与POSE(0x82，64字节载荷/76字节总长)轮流发送，空闲USB时各20Hz。
两类反馈共用反馈帧头sequence，每次成功交给USB后递增；忙/未连接会增加tx_skipped，保留待发送类型，下次重新编码最新快照再尝试，不积压旧帧。
传输受USB主机读取及总线繁忙影响，20Hz不是硬实时交付保证；“提交成功”不表示上位机已消费。
原0x81字段布局不变，但只接收旧STATUS的解析器应忽略新的0x82，并允许STATUS帧序号不连续。
FireWater模式1保持原22通道20Hz，不发0x82。正式对接应使用模式0。
