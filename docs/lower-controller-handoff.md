# STM32 下位机交接：USB CDC v1

本工程交付范围为STM32固件和USB通信协议。ROS 2 节点、串口驱动/桥接、导航、坐标变换、TF及上位机部署由上位机负责人实现和维护。STM32已根据四轮编码器积分并上传相对起点的X/Y/yaw，上位机可转换为Odometry；若需要重定位/融合定位，由上位机负责，不能把上传位姿再当作位移增量积分。STM32不直接订阅ROS话题；上位机按下述协议收发USB帧即可使用下位机连续控制，不需要任何短时运动测试程序。

## 硬件与坐标约定

- MCU：STM32F407VET6；上位机通过MCU原生USB FS CDC连接，PA11=D−，PA12=D+。接口在USB配置后周期上传状态，不依赖DTR；CDC line coding的115200不决定USB链路速率。
- 电机：EMM V5.0，UART5 TTL 115200/8N1，共四地址：1左前、2右前、3右后、4左后。电机UART的0x6B校验尾与本USB协议的CRC不同。
- 速度坐标：x前，y左，z上；正wz为俯视逆时针。SI接口vx/vy使用m/s，wz使用rad/s；在线payload使用对应的整数毫单位。
- 四全向轮X型45°，轮径75 mm、无减速；轮距/轴距暂用240/240 mm。四轮SI安装符号−1，已同时用于目标和实测轮速；原始位置不反转。

## 上位机必须实现的收发契约

帧结构（小端）：

```text
A5 5A | 01 | type:u8 | payload_len:u16 | sequence:u32 | payload | crc16:u16
```

CRC-16/CCITT-FALSE覆盖帧头到payload，poly=0x1021、init=0xFFFF、不反射、无末尾异或。标准向量`123456789 → 0x29B1`。允许USB拆包/粘包，不能把一次串口读取当一帧；帧总长=payload_len+12。

| type | 方向 | payload |
| --- | --- | --- |
| 0x01 VELOCITY | 上位机→STM32 | 3×int32：vx mm/s、vy mm/s、wz mrad/s，长度12 |
| 0x02 ARM | 上位机→STM32 | 空，长度0，可选零速预使能 |
| 0x03 STOP | 上位机→STM32 | 空，长度0 |
| 0x04 POSITION | 上位机→STM32 | 3×int32：绝对X mm、Y mm、yaw mrad，长度12 |
| 0x81 STATUS | STM32→上位机 | 长度196，总帧208字节，名义20Hz；字段见主协议 |
| 0x82 POSE | STM32→上位机 | 长度64，总帧76字节，名义20Hz；字段见位置扩展 |

共四个控制消息，无文本控制命令；两种二进制反馈交替发送，必须按type和length拆帧，不能假设所有帧都是208字节。STATUS包含主机控制state/fault、最后接受的ARM/VELOCITY/POSITION序号、命令拒绝与总线错误计数、目标/实测底盘速度、四轮原始累计位置/实测轮速/使能/堵转及有效性和MCU时间。没有通用ACK，需依据状态和序号确认执行。STOP不更新接受标记；sequence只回传、不去重，不能只靠标记判断实物已执行。

协议示例：

```text
ARM(seq=1):
A5 5A 01 02 00 00 01 00 00 00 4B 4C

VELOCITY(seq=0xFFFFFFFF, vx=-50 mm/s, vy=25 mm/s, wz=-300 mrad/s):
A5 5A 01 01 0C 00 FF FF FF FF CE FF FF FF 19 00 00 00 D4 FE FF FF 47 91
```

## 正常控制时序

1. USB连接后先读取STATUS，确认反馈模式0，首次连接代次已经被处理。
2. 直接发送VELOCITY。固件保存目标，待总线和四轮反馈正常且失能后自动开始使能，再进入ACTIVE执行目标，无需ARM。
3. 需要改变速度时发送新的VELOCITY；也可持续发布。sequence可固定为0，无最小发布频率或主机命令超时。使能期间非零速度有效。
4. 零速度表示零速保持；需要停止失能时发送STOP，并查看四轮新鲜失能反馈。STOP所在接收批次的后续输入丢弃。

ARM保留为可选零速预使能，运行或已有启动请求时重复ARM忽略。启动等待中也可更新目标，STOP会取消待启动请求。设备故障、USB挂起/重新配置或接收溢出会清除旧目标；恢复后发一条新的VELOCITY即可重新申请启动。

偶发查询超时或协议错误计数增加不再单独停车；控制写失败、明确拒绝、反馈过期、堵转及UART故障仍停止。底层200 ms周期输出检查由motorTask持续刷新满足，与主机发布频率无关。

ROS 2负责人将`/cmd_vel`三轴转换为上述整数毫单位。主机停止发布、ROS节点退出但USB仍连接时，下位机会保持最后速度；停车需要发送零速度或STOP。USB物理拔线依赖挂起/断开事件识别，无命令静默超时兜底。STM32工程不维护ROS桥接代码。

## 位置控制对接

1. 连接后读取STATUS和POSE，确认模式0、定位可用（flags bit0）且底盘不在STOPPING。
2. 上位机将自身坐标系的目标转换到STM32启动时固定坐标系；X/Y乘1000转mm，yaw（弧度）乘1000转mrad，再按0x04发送三个int32。无需ARM或持续续发；重复坐标不追加行程。
3. 检查POSE的目标整数坐标、位置命令sequence和goal_generation，确认对应请求已接受；不满足定位条件或处于STOPPING时会拒绝，仅增加control_rejected。
4. 收到有效POSE且robot_mode=2、arrival_state=3、flags低四位均为1时，可认定当前目标稳定到达。到达后保持使能和位置；偏离容差或低速条件失效会撤销到达。
5. 新POSITION覆盖目标；VELOCITY（包括零速）切换到速度模式；STOP取消并请求失能。ARM在位置模式中忽略。故障恢复后需要新的外部命令。

当前位置环kp_xy=0.5、kp_yaw=1.0，距离容差5mm、yaw容差约1°；稳定条件为实测平移<=10mm/s、角速度绝对值<=20mrad/s持续至少300ms。该参数不等于真实世界定位精度。完整偏移、有效标记、坐标原点及CRC示例见[position-feedback.md](position-feedback.md)。

## 当前参数边界与反馈有效性

| 参数 | 当前设置 |
| --- | --- |
| vx/vy输入范围 | int32整数mm/s；解算结果须在驱动协议范围内 |
| wz输入范围 | int32整数mrad/s；解算结果须在驱动协议范围内 |
| 底盘软件速度上限 | 无；直接解算，不做比例缩放 |
| 驱动协议速度范围 | 原生±5000字段单位，名义1 RPM/单位 |
| 主机速度命令期限 | 无；最后目标持续保持，直到新命令/STOP或实际故障 |
| 使能确认期限 | 开始实际使能操作后500 ms；期间可保存非零目标，无须续期 |
| 停止确认期限 | 1000 ms |
| 二进制上传 | STATUS/POSE每25ms轮换，各名义20Hz；USB忙时下一次发送该类型的最新快照，不积压旧帧 |

底盘不再施加软件速度上限。驱动协议原生范围不代表实际电机可达到的性能；任一轮目标超出该范围时进入MOTOR_ERROR并停止，不缩放、不截断或回绕。

原始`position_raw`为带符号累计位置，暂按65536计数/圈，不是世界坐标绝对位姿。实测轮速已应用安装符号，上位机不要再次反转速度；若自行从原始位置解算轮轴角度，使用`-position_raw×2π/65536`。位置每圈比例及精确几何尚未完成完整标定；当前速度命令按名义1 RPM/字段单位换算，此前字段20实测约19.08 RPM，未据此拟合补偿。

目标与实测独立传输，`requested`/`applied`均非实际运动反馈。无效速度的int32字段为INT32_MIN，须检查有效位。MCU提供的底盘实测速度仅在四轮测量有效、新鲜、采样时间差满足限制时有效，不能用目标替代无效反馈。MCU毫秒时钟未与ROS同步，ROS时间戳转换、POSE到Odometry映射及TF由上位机处理；POSE已是积分后的绝对位姿，不再作位移增量积分。

state：0 DISABLED，1 ENABLING，2 ACTIVE，3 STOPPING，4 FAULT。fault及全部反馈偏移见完整协议。UART5目前顺序发送四轮速度，未实现驱动器同步触发；反馈亦非硬件同步采样。
