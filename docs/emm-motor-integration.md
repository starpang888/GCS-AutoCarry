还核对了上述仓库根目录的 `ZDT_X42S第二代闭环步进电机用户手册V1.0.5_260527.pdf`：第 50 页 F3 AB 使能、第 60 页 FE 98 停止与 FF 66 同步触发、第 72 页位置符号 / 幅值、第 73—74 页状态位域。手册同时列出 Emm / X 固件；两者查询帧相同，但位置单位（65536/圈或 0.1°）和速度指令不同，不能从当前零位置回包确定这些差异。现有速度构帧仅针对 Emm 风格示例，未进行运动验证；实物固件类型、限速和输入分辨率确认前不接入底盘运动。

烧录修正版后在 Watch 查看 `motor_status`：

- 四个 `wheels[0..3].position_valid / enabled_valid / stall_valid` 应持续为 true；上电失能后 `enabled=false` 是正常结果，不等于 `enabled_valid=false`。

### 四轮反馈正常后 rejected_commands 持续增长的修复

用户已纠正型号为 EMM V5.0，并确认四轮反馈正常。运行中只读诊断与当时 ELF 的烧录记录匹配，读到 `last_rejected_address=1`、`last_rejected_function=0xFE`、`last_rejected_status=0xE2`；`transaction_timeouts=0`、`protocol_errors=0`，四台 `enabled_valid=true` 且 `enabled=false`。两次读取的拒绝数从 824 增至 930，间隔约 26.3 秒，与 250 ms 重复停止的频率一致。

原调度在已确认全部失能时仍每 250 ms 发送 FE，目标在该状态下返回 E2。现仅在全部使能反馈新鲜且均失能时省略周期重复停止；反馈未知、过期或任一电机仍使能，继续发送。显式/故障停止与启动停止→失能顺序保留，不能将所有 E2 改成成功或清零计数。启动时状态未知，首次停止仍可能被已失能驱动拒绝一次，因此验收看计数是否持续增长，不要求历史累计值必为 0。

新增测试覆盖全部新鲜失能时无重复发送、任一使能或反馈过期时恢复发送、显式停止不省略，以及启动 FE/E2 后仍发失能并保留真实错误计数。最新固件上板效果仍待烧录确认。

## 文件与运行路径

| 文件 | 职责 |
| --- | --- |
| `bsp/uart/bsp_uart.c/.h` | HAL 收发、DMA 及中断回调、接收环形缓冲、发送缓冲所有权、故障恢复 |
| `modules/motor/emm/emm_bus.c/.h` | 唯一串口事务调度、响应匹配、队列、超时、运动许可和停止仲裁 |
| `modules/motor/emm/emm_motor.c/.h` | 地址实例、速度 / 使能命令、位置与状态反馈、轮轴单位换算 |
| `board/board_motor.c/.h` | UART5、地址顺序、轮径 / 间距 / 方向配置、构造及轮询实例 |
| `system/robot_task.c/.h` | 静态 motorTask、任务心跳、一致的反馈快照 |

```text
MX_FREERTOS_Init
  RobotTaskInit
    BoardMotorInit：构造 BSP、一个总线、四个电机实例
    创建 motorTask / statusTask
osKernelStart
  motorTask：启动循环 DMA
    BoardMotorUpdate：UART 恢复 → 消费字节 → 协议解析 → 查询调度 → 总线更新
    复制反馈快照 → 上报任务进度 → osDelay(1)
```

motorTask 使用 Normal 优先级、静态 512 word / 2048 B 栈。循环延时不代表精确的 1 kHz 控制频率。每 5 ms 尝试安排一个查询，8 个轮询槽分别为四台位置、四台状态（同帧包含使能与堵转）；正常名义轮询周期约 40 ms，事务超时和调度会延长实际间隔。

串口与全部 EMM API 由 motorTask 单独拥有；不能从 ROS 任务或 ISR 直接调用电机实例接口。将来接入控制时，通过有同步保证的命令快照交给这个拥有者。其他任务当前可用 `RobotMotorGetStatus()` 复制一致状态，返回 false 表示首个电机周期尚未完成。其数据仍包含各字段采集时间和有效性；接口会在读取时重新检查超时。

## 当前上电行为

1. 发送广播立即停止 `00 FE 98 00 6B`，同步标志为 0，立即执行。
2. 发送广播失能 `00 F3 AB 00 00 6B`。
3. 按地址组织位置 `0x36` / 状态 `0x3A` 查询；任何时刻只有一个事务在途。
4. 保持无运动许可，每 250 ms 检查是否需要重复立即停止：仅在全部已注册电机使能反馈未过期且均为失能时省略；任何一台使能、反馈未知或过期时仍发送。显式停止、故障停止不受该省略规则影响。

默认上电路径没有自动使能、运动许可或非零速度调用，不执行清零、校准、回零、解除堵转及持久化参数命令。正式版由 `application/robot.c` 编排USB连续控制，已删除旧手动运动入口；协议见 `docs/usb-cdc-host-link.md`，既往方向/速度核对结果见 `docs/chassis-calibration-record.md`。停止依赖 MCU 和总线仍能工作；这里没有硬件急停或驱动器独立看门狗的保证。任务状态灯监测 defaultTask 和 motorTask 的执行进度；即使四台电机未接上，任务仍可能正常运行并慢闪，电机在线情况应看反馈有效性和错误统计。

## 控制接口及停止行为

- `EmmMotorQuery()`：`EMM_QUERY_POSITION` 对应 `0x36`，`EMM_QUERY_STATUS` 对应 `0x3A`；使能与堵转由同一个状态位域提取，不发送 `0x3E`。同设备同类型的待发查询合并。
- `EmmMotorSetEnabled(true)`：提交单台使能请求。写应答不等于实际使能，必须通过查询确认。
- `EmmBusArm()`：显式申请运动许可，要求已注册的全部电机位置、使能和堵转反馈新鲜，且实际已使能、未堵转、无堵转保护。启动 / 故障后不自动恢复运动许可。
- `EmmMotorSetSpeedUnits()`：驱动器原生有符号速度字段，范围 -5000…5000，正为驱动器 CW、负为 CCW；同一电机待发速度覆盖旧值。速度帧为 `地址 F6 方向 速度高字节 速度低字节 加速度 00 6B`，加速度 0 表示直接启动，不采用旧版的 0xFF 语义。
- `EmmMotorSetSpeed()`：轮轴 rad/s 接口，仅在板级配置经过验证的 `wheel_rad_s_per_speed_unit` 后可用；当前为 0，因此返回 false。同类 V5 示例为 1 RPM/字段单位，较新固件存在 0.1 RPM 选项，需核实实物设置。1 RPM、直驱时系数为 `2*pi/60`；0.1 RPM 时为其十分之一。安装方向仍待标定。
- `EmmMotorStop()`：停止整条底盘总线；`EmmMotorSetEnabled(false)`：停止并失能整条底盘总线，避免剩下三个轮继续运动。

已授权运动时，每个电机的速度目标都必须在 200 ms 内刷新。一个电机刷新不能替其他轮续期。任何电机反馈过期、失能、堵转、控制写失败、驱动明确拒绝、传输异常或速度目标队列满，会撤销许可并清空待发送队列，优先安排全体停止 / 失能。反馈超时为500 ms。2026-11-01简化：查询偶发超时保留尚新鲜的反馈继续轮询，协议错误计数增加不再单独触发应用停止。此200 ms是motorTask周期输出检查，主机无需续发速度，当前VELOCITY自动使能并保持目标，见USB协议。

停止不覆写在途 DMA 的发送数据；待该帧发送完成后，放弃旧事务等待，优先发立即停止。UART BSP 对 TX 使用独立 20 ms 截止时间，故障恢复在任务内执行 HAL 的有限时 abort；不会在关中断区或 ISR 里等待。单个在途速度帧可能已被驱动执行，所以软件停止不是零延迟的物理急停。

## 反馈与协议边界

位置响应为 `地址 36 符号 幅值[4字节大端] 6B`，符号 0 为正、1 为负；原始值用 int64_t 保存完整的 ±4294967295 范围。目前按同类 V5 示例的每转 65536 个计数换算，实物需手转一圈核实比例。反馈保存原始计数、轮轴位置 rad、相邻有效位置差分得到的平均速度 rad/s、位置 / 使能 / 堵转各自的时间和有效性。首个样本、相同毫秒或跨越反馈超时的样本不产生有效速度；计数跨界、清零等异常跳变不假定模差规则，超过同类协议 5000 RPM 上限的差分样本标记为速度无效。当前反馈时间为任务接收处理时的 MCU 毫秒时间，不能称为硬件采样时间或已经与 ROS 时钟同步。

四个安装方向暂填 +1，仅表示原生 CW 正向，尚未标定为底盘轮轴正方向；底盘应用不得据此直接驱动车体。标准 X 型四全向轮数学解算和目标预览已接入，见 `docs/omni-chassis-kinematics.md`，当前不触发电机输出。后续实测尺寸修改 `board_motor.c`，方向、单位映射确定后再接入底盘联动输出。

响应包含功能码，没有事务序号。模块按唯一在途请求、地址、功能码、预期长度、符号范围及帧尾解析，支持分片、连续数据及错误帧后的重新同步。状态 `地址 3A flags 6B` 保存完整 status_raw：bit0 为使能、bit2 为堵转、bit3 为堵转保护，高位不作 0/1 范围校验。写 ACK 为 `地址 功能码 02 6B`；`地址 00 EE 6B` 或写应答非 02 状态直接记录拒绝，并触发停止仲裁。查询偶发超时仅保留尚新鲜反馈继续轮询；超时后保持至少40 ms隔离且总线空闲2 ms，再发普通事务；期间仍允许优先停止 / 失能。安全命令的正常 ACK 不会缩短失败事务隔离。固定 `0x6B` 无法检测所有有效载荷位错误，超出隔离窗口的同地址同功能迟到响应也无法被协议完全区分，上板需验证应答延迟及无串口回显。

RX 使用 128 B 循环 DMA 和 256 B 软件环形缓冲，保留 HT / TC / IDLE 事件；ISR 读取实时 NDTR，避免过时事件的 Size 导致重复消费。溢出不覆写未读数据，而是标记故障、作废事务并恢复接收。HT 和 TC 要及时响应；若中断阻塞至 DMA 已绕过一整圈，单靠 NDTR 无法重建丢失圈数，本阶段单元测试不能证明实物中断时序。
