# VOFA 反馈查看

正式固件发送 `A5 5A` 帧头的自定义二进制协议，供上位机按协议对接。VOFA 文本窗口会把二进制显示成乱码，FireWater / JustFloat 插件也不能直接解析那种帧；仅修改波特率或字符编码不能解决协议不匹配。

固件已增加 **FireWater** 输出，用户已确认显示正常。正式下位机默认使用二进制（模式0）；要按本文使用VOFA，先在静止时选择 `host_feedback_mode=1` 并恢复运行确认 `host_status.feedback_mode=1`，或把板级默认设为1后编译烧录。每 50 ms 发送一行纯 ASCII 数字，逗号分隔、CRLF 结尾，不混入二进制 STATUS 或其他日志。上传不会使能电机；旧单轮/四轮运动模块和调试启动入口已删除，停止使用USB STOP命令。

## 使用步骤

1. 烧录最新 `build/Debug/GongChuangsai.elf`。本次助手只构建、模拟测试，未代为烧录。
2. 连接 MCU 原生 USB FS 口，VOFA 选择该 CDC 的 COM 口。
3. 正式下位机固件需先在静止时选 `host_feedback_mode=1`，恢复运行确认 `host_status.feedback_mode=1`；再选择串口数据源，115200 / 8N1，数据协议选择 **FireWater**。不要选择 JustFloat 或 RawData。
4. 打开连接并添加相应通道到波形图；原始接收窗口应能看到逗号分隔的数字文本。

CDC 的 115200 只是电脑端 line coding，不决定 USB 实际传输速度；与电机 UART5 的 115200 是两回事。同一 COM 口同一时间只由 VOFA 或上位机控制程序之一占用。

## 22 个通道（以下从 0 编号）

四轮顺序始终为 1 左前、2 右前、3 右后、4 左后。

| 通道 | 内容 | 单位/解释 |
| --- | --- | --- |
| 0 | 主机底盘控制 state | 0失能、1使能中、2运行、3停止中、4故障 |
| 1 | 主机底盘控制 fault | 0正常、1命令超时保留值、2链路异常、3电机错误、4使能超时、5停止超时、6内部运动学输入异常、7位置模式定位不可用 |
| 2 | 总线 motion_allowed | 0/1；当前总线是否允许运动 |
| 3…6 | 四轮实测轮轴速度 | rad/s，已应用安装符号 −1；例如 20 RPM 约 2.094 rad/s |
| 7…10 | 四轮 position_raw | 驱动器原始累计位置，保留原生符号，暂按 65536计数/圈 |
| 11 | transaction_timeouts | UART 电机事务超时累计次数 |
| 12 | protocol_errors | UART 电机协议错误累计次数 |
| 13 | rejected_commands | UART 电机驱动器拒绝命令累计次数 |
| 14 | transport_errors | UART 传输错误累计次数 |
| 15 | rx_errors | UART 接收错误累计次数 |
| 16 | 位置有效掩码 | 四轮全有效为 15 |
| 17 | 轮速有效掩码 | 四轮全有效为 15；无效轮速以 0.000 占位，不能视为实测静止 |
| 18 | 使能反馈有效掩码 | 四轮全有效为 15 |
| 19 | 已使能掩码 | 四轮全失能为 0、全使能为 15；仅统计有效反馈 |
| 20 | 堵转/堵转保护掩码 | 正常为 0；仅统计有效反馈 |
| 21 | MCU uptime_ms | RTOS 毫秒，持续递增、uint32 回绕 |

所有掩码 bit0…bit3 对应地址 1…4。例如位置有效掩码 13（二进制1101），表示轮1/3/4有效、轮2无效。通道0/1是 USB 主机控制状态；通道2、四轮速度和使能掩码反映总线实际状态。

位置样本无效时仍可显示上次原始数值，需结合通道16判断；轮速无效的0.000需结合通道17。轮速来源是位置差分，未使用目标值代替反馈。

## 切回二进制模式

正式下位机的默认设置位于 `board/board.h`：

```c
#define BOARD_HOST_FEEDBACK_DEFAULT 0U
```

0为二进制STATUS/POSE（两类各名义20Hz），1为VOFA FireWater（22通道20Hz）。改默认值后重新编译、烧录；也可在静止时用调试器把保留选择器 `host_feedback_mode` 写为0或1，恢复运行后查看 `host_status.feedback_mode` 的确认值。固件不自动清零选择器，复位后恢复板级默认值。存在待启动速度或主机控制处于 ENABLING/ACTIVE/STOPPING 时不切换输出格式，需先停止。

二进制模式不混入文本；其中STATUS与POSE按帧类型区分并轮流发送。FireWater模式只发送文本，不包含POSE位姿/到达字段；需要这些字段时使用模式0或调试器观察chassis_pose/chassis_arrival_status。二进制帧结构保持v1，当前控制语义为速度自动使能及目标保持（2026-11-01修订），FireWater只用于观测；不要在 VOFA 中发送随意文本作为运动命令。上位机的正式二进制通信要求反馈模式0，FireWater 模式下它们无法解析状态。详见 [USB 二进制协议](usb-cdc-host-link.md)。
